Data Catalog, Business Screens
& What "Drill" Really Costs

TL;DR #2 — Themis turns raw risk data on S3 into governed, business-facing screens where an analyst can slice, drill and re-aggregate on demand — and the admin config layer lets the business shape those screens without a code release.

1 · From raw data to a business screen

Catalog is automatic · Views are admin-configured · Screens are what business users touch.

2 · The Data Catalog — always-fresh, zero setup

  • Auto-connects with the backend's credentials + CDH project profile — users never run a "connect" step.
  • Background S3 location index, refreshed ~every 15 min using stale-while-revalidate — the old index keeps serving while the new one builds, so the catalog never goes dark.
  • Read-only browse: databases → tables → schemas, and buckets → paths.

Business value: a single, governed entry point — people discover what exists without AWS access or tickets.

3 · Views — the business configures its own screens

  • Definition = name + feeding tables + dimensions + measures + optional worst-scenario config.
  • Measures carry an additive flag — the single most important piece of metadata (see §5).
  • Grain links attach a coarse level to a finer one — what makes drill-down navigable.
  • Caching is per-view (TTL + manual refresh) so hot screens stay fast without stale numbers.
  • Governance: reads open to any authenticated user; writes need an admin role and are audit-logged.

Headline: a new dimension, measure or drill path is an admin config action, not a software release. The dev team is not a bottleneck for everyday screen changes.

4 · What the screens do

All read-only, against curated tables through the shared catalog (via Athena).

ActionBusiness meaning
Filter / sliceScope to a date, source, channel, book, etc.
Drill-downExpand one node to the next-finer grain (desk → book → trade).
Drill-throughList the underlying constituents (the actual trades behind a number).
Per-scenarioDecompose a risk number across its scenarios.
Re-aggregateRecompute a measure for an arbitrary grouping the user picks on the fly.

5 · The key insight: additive vs non-additive

Why some numbers are cheap & instant and others are expensive.

Additive

Notional, P&L …

re-agg = SUM

Fast, exact, done in the query. Drilling & regrouping is effectively free (in-query Athena SUM).

Non-additive

VaR / risk-vector figures …

VaR(book) ≠ Σ VaR(trades)

Must re-compute from the underlying risk vectors, element by element across scenarios — or a Spark recompute for the complex case.

Many tools silently sum VaR and produce wrong numbers. Themis refuses to — it does the correct non-additive roll-up, chosen automatically from the additive flag.

6 · The honest performance trade-off

The expensive part is the correct non-additive risk math, not the UI. That's exactly where the team's optimisation effort is focused — inherent to giving the business correct VaR at any grouping, on demand.

One-slide summary

  • Catalog → Views → Screens: a governed path from raw S3 risk data to business drill screens.
  • Views are admin-configured — the business reshapes its own screens without a code release, all audit-logged.
  • Slice / drill-down / drill-through / per-scenario / re-aggregate — the full toolkit, read-only against curated data.
  • Additive vs non-additive is the key insight: Themis sums what can be summed and correctly re-computes VaR when it can't.
  • Net: correct & interactive answers — the compute cost lives in the correct risk math, where the engineering investment is going.
